# Face Access System — распознавание лиц на проходной офисного кампуса
- - -
## 1. О решении
Система автоматического контроля доступа в офисный кампус с использованием распознавания лиц. Камера на проходной захватывает кадр, система детектирует лицо, проверяет качество изображения и liveness (признак "живости"), извлекает эмбеддинг, сравнивает с базой сотрудников и принимает решение: открыть турникет (allow), отправить на ручную проверку охране (manual_review) или закрыть доступ (deny).

**Архитектурные слои:**

    
- **Edge-устройство (на проходной):** детекция лица, оценка качества, liveness, извлечение эмбеддинга
    
- **Центральный сервис:** поиск по базе (ANN-индекс), принятие решения, аудит
    
- **Ручной контроль:** интерфейс для охраны для обработки сомнительных случаев


**Ключевая особенность:** система не открывает турникет автоматически при любом совпадении, а принимает решение на основе порогов, учитывая цену ошибок:

    
- **False accept (пропуск постороннего)** — критический инцидент безопасности
    
- **False reject (блокировка сотрудника)** — потеря времени и рост очереди

## 2. Как запустить Proof-of-Concept
### Требования

    
- Python 3.8 или выше
    
- Установленные зависимости из `poc/requirements.txt`


### Команды для запуска
    # Перейти в папку с PoC
    cd poc
    
    # Установить зависимости
    pip install -r requirements.txt
    
    # Запустить демо
    python main.py

### Демонстрируемые сценарии
**Happy path (успешный проход):**

    
- **Вход:** качественное фото сотрудника из базы
    
- **Процесс:** лицо найдено → качество OK → liveness OK → матчинг с базой → решение allow
    
- **Выход:** турникет открыт, событие залогировано


**Risky path (сомнительный случай):**

    
- **Вход:** фото с плохим качеством, неизвестное лицо, низкий liveness
    
- **Процесс:** лицо найдено, но качество/liveness ниже порога → решение manual_review
    
- **Выход:** турникет НЕ открыт, событие отправлено охране на ручную проверку


**Важно:** PoC использует упрощенные компоненты (Haar Cascade вместо YOLO-Face, mock-проверка liveness), но полностью воспроизводит логику принятия решений и поток данных целевой архитектуры.

## 3. Архитектурный дизайн
### Реализовано в PoC (код)

    
- Детекция лица с использованием OpenCV (Haar Cascade)
    
- Простая оценка качества (размер лица, резкость)
    
- Извлечение эмбеддинга с использованием библиотеки face_recognition
    
- Сравнение с базой через косинусное сходство (в production — FAISS)
    
- Логирование всех решений в JSON-формат
    
- Два сценария: allow и manual_review

## 6. Бизнес-ценность системы
Система решает три ключевые бизнес-задачи:

    
1. 
            
  **Ускорение прохода сотрудников**
            
                    
    - Сокращение времени в утренний пик с 90 секунд до менее 1 секунды на человека
        
                    
    - Экономия около 283 000 рублей в год за счет снижения потерь рабочего времени
        
                
    
        
    
1. 
            
  **Разгрузка охраны**
            
                    
    - Автоматизация ручного разбора забытых карт (40 случаев в день, 4 минуты на случай)
        
                    
    - Экономия около 56 000 рублей в год
        
                    
    - Высвобождение времени охраны для более важных задач
        
                
    
        
    
1. 
            
  **Повышение безопасности**
            
                    
    - Исключение возможности передачи карты коллеге или постороннему
        
                    
    - Автоматическая фиксация всех попыток прохода с audit-логом
        
                
    
        

**Итоговый экономический эффект:**

    
- ~400 000 рублей в год
    
- CAPEX на 3 проходные: 630 000 рублей
    
- Окупаемость: ~1.6 года
